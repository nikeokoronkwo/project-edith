What the Data Actually Tells Us

The Dataset at a Glance

The CSV covers Jan 1–17, 2026 with hourly readings across 5 sectors (Wakanda, New Asgard, Sokovia, Sanctum Sanctorum, Avengers Compound) and 5 resources (Vibranium, Arc Reactor Cores, Pym Particles, Clean Water, Medical Kits). There are 39 rows flagged as "snap events" — all clustered at hours 19:00 and 20:00 on Jan 1. The snap appears to cause sudden ~50% stock drops across all sectors simultaneously. The JSON has 200 field reports from 6 heroes, 34 of which leak hero names directly in the raw_text body. Priorities split roughly evenly: 76 Routine, 63 High, 61 Avengers-Level Threat.

Architecture Directions (40% of Score)

Architecture

Event-Driven Microservices

Separate services for ingestion, PII redaction, LLM processing, forecasting, and dashboard API. Connect via message queue (Redis pub/sub or simple event emitter). Each service independently deployable and testable.

↗ Shows "separation of concerns" they asked for. Impressive on architecture rubric.
Architecture

Monolith with Clean Layers

Single Node/Python backend with clearly separated modules: /routes, /services/redaction, /services/forecast, /services/llm, /models. Faster to build, easier to demo. Still scores well if well-structured.

↗ Pragmatic for a hackathon. Focus energy on features instead of infra.
Architecture

Serverless / Edge Functions

Deploy redaction as a Cloudflare Worker or Lambda. Dashboard as static SPA. Backend as serverless functions. Shows modern cloud-native thinking.

↗ "Security middleware as a separate edge function" is a great talking point
Architecture

Real-Time WebSocket Pipeline

WebSocket connection between frontend and backend. When a report is submitted, the entire processing pipeline streams status updates back to the UI in real-time: "Received → Redacting → Processing → Classified → Done".

↗ "Does the UI update without a full page refresh?" is literally on the checklist
Architecture

Data Lake + Stream Processing

Historical data in a time-series optimized store (TimescaleDB or InfluxDB). New reports stream through a processing pipeline. Separate hot path (real-time alerts) and cold path (forecasting batch jobs).

↗ Enterprise-grade thinking. Overkill for a hackathon but jaw-dropping if pulled off.
Architecture

GraphQL API Layer

Instead of REST, expose a GraphQL API. The frontend can query exactly the data it needs for each widget — stock levels for one chart, forecasts for another, intel for a third — in a single request.

↗ Clean, modern, shows API design sophistication
03

Intelligent Processing Ideas (20% of Score)

ML/Forecasting

Snap-Aware Time Series Forecasting

Don't just do linear regression. Detect snap anomalies first, then train on "normal" data only. Show two forecast lines: "baseline" and "post-snap recovery." Calculate time-to-zero for each. The judges specifically ask about handling Thanos Snap anomalies.

↗ Directly addresses the Q&A question from the checklist
ML/Forecasting

Monte Carlo Depletion Simulation

Instead of a single prediction line, run 1000 simulations with randomized usage rates (sampled from historical variance). Show a probability fan/cone on the chart — "70% chance Vibranium depletes by Feb 3, 95% by Feb 10."

↗ Way more impressive than a single regression line. Visual impact is huge.
AI/NLP

LLM Entity Extraction → Structured Intel

Send redacted report text to LLM with a structured prompt: "Extract: sector, resource_type, severity, action_needed." Parse JSON response into a live intelligence table. This is the core ask.

↗ This is the baseline expectation. Must have this.
AI/NLP

Sentiment + Urgency Scoring

Go beyond entity extraction. Have the LLM also score each report on urgency (1–10) and sentiment (panic, calm, desperate). Use this to auto-prioritize the intel feed and color-code entries on the dashboard.

↗ Differentiation. Most teams will just extract entities.
AI/NLP

Cross-Reference Intel with Historical Data

When a report says "Wakanda is critically low on Vibranium," automatically cross-reference with the CSV data. If the historical data confirms the claim, boost confidence. If it contradicts, flag as potential misinformation or outdated intel.

↗ Shows integration between the two datasets — exactly where "the magic happens"
ML/Forecasting

Anomaly Detection Engine

Build a real-time anomaly detector: Z-score or isolation forest on incoming data. When a new reading deviates >2σ from the sector's norm, auto-flag it as a potential snap precursor. Show a "threat level" indicator.

↗ "Predict events before they happen" — this is the precognition angle
AI/NLP

Conversational "Jarvis" Interface

Instead of just a dashboard, add a chat interface. Users can ask: "What's the most critical sector right now?" or "When will medical kits run out in Sokovia?" and get natural language answers backed by the data.

↗ The dev guide literally calls this "The Jarvis Layer" — lean into it
AI/NLP

Auto-Generated Situation Reports

Every hour (or on-demand), have the LLM synthesize all recent intel + current stock levels into a natural language "SITREP" briefing. "Commander, Wakanda Vibranium is at 12% with 6 hours to depletion. Three high-priority reports flagged from that sector in the last hour."

↗ Extremely demo-friendly. Judges see one paragraph that shows everything working together.

Security & Privacy Ideas (20% of Score)

The Critical Demo Moment

The presentation checklist says: "CRITICAL. Show the request sent to the LLM. Prove that hero names and phone numbers were redacted before leaving your server." This means you need a visible log/debug panel showing the before → after of redaction. This is non-negotiable.

Security

Multi-Layer PII Redaction Pipeline

Layer 1: Regex for phone patterns (555-XXXX, etc.). Layer 2: Dictionary lookup against known hero names. Layer 3: NER model (spaCy or compromise.js) to catch any names the dictionary missed. Log each layer's catches separately.

↗ Shows defense-in-depth thinking. Way stronger than regex alone.
Security

Tokenization Instead of Redaction

Instead of replacing names with [REDACTED], replace with reversible tokens: "Tony Stark" → "[HERO-7F3A]". After LLM processing, de-tokenize for authorized viewers. This preserves analytical utility while protecting identity.

↗ More sophisticated than simple redaction. Shows you thought about data utility.
Security

Audit Trail / Security Log

Every redaction event gets logged with timestamp, report_id, what was redacted, and which layer caught it. Expose this as a "Security Audit" tab in the dashboard. Proves compliance.

↗ Visual proof of security for the demo. Judges love this.
Security

Role-Based Access Control (RBAC)

The checklist asks: "Is the Admin/Analytics view differentiated from the Input view?" Build two roles: "Field Operative" (can submit reports, see redacted intel) and "Commander" (sees full analytics, forecasts, raw audit logs).

↗ Directly addresses a checklist item most teams will skip
Security

Real-Time Redaction Diff Viewer

In the UI, show a side-by-side: original report on the left, redacted version on the right, with redacted items highlighted in red. This IS the security demo moment. Make it theatrical.

↗ This is your "wow" security moment during the 5-minute pitch
Security

Encrypted At-Rest Storage

Store hero identities in an encrypted column in the DB. Even if someone queries the database directly, they can't see names without the decryption key. Show this in the demo by running a raw DB query.

↗ Goes beyond the brief. Shows enterprise security thinking.

The Meta AI Glasses / "Jarvis" Angle — Deep Dive

Your Big Idea: Meta Ray-Ban Glasses as Field Collection Device

This is a strong differentiator. The concept: field operatives wear smart glasses that can capture visual intel, voice-dictate reports, and stream data back to the C2 dashboard — with the AI acting as "Jarvis" in their ear. Here's how to think about it from multiple angles:

Hardware + AI

Voice-to-Intel Pipeline

Operative speaks: "Sokovia warehouse, Vibranium reserves look low, maybe 200kg left. Civilians are rationing." → Whisper STT → PII redaction → LLM extracts: {sector: Sokovia, resource: Vibranium, estimated_stock: 200, severity: high} → Dashboard updates.

↗ Shows the full pipeline from voice to dashboard. Extremely demo-able.
Hardware + AI

Visual Inventory Assessment

Operative points glasses camera at a supply shelf → image sent to vision model → AI estimates stock count → auto-generates a stock update report → dashboard reflects new reading. "Computer vision for resource counting."

↗ Combines vision AI + the data pipeline. Mind-blowing if demoed live.
Hardware + AI

Heads-Up Display (HUD) Concept

Even if you can't build actual AR, design a "what the operative sees" view in the dashboard. Show a simulated HUD overlay: sector status, nearest supply cache, alert level, and a mini-map. This sells the vision without needing hardware.

↗ You can demo the concept with just a React component — no glasses needed
Hardware + AI

Jarvis Audio Briefings

When an operative enters a sector (or on demand), Jarvis speaks a contextual briefing: "Entering Wakanda sector. Vibranium at 34%, estimated 8 hours to depletion. Three active high-priority reports. Medical kits stable." Use browser TTS or ElevenLabs.

↗ The name "Jarvis" is IN the dev guide. They want this.
Hardware + AI

Hands-Free Report Dictation

Build a "Field Mode" in the UI optimized for voice: big buttons, voice-activated commands, no typing needed. "Jarvis, log a report: Medical kits critical in Sokovia, need resupply within 4 hours." Could work with Web Speech API.

↗ Accessibility angle + practical field use case + uses browser APIs
Hardware + AI

The "Prevent the Snap" Predictive Alert

If the anomaly detection engine detects snap-like patterns (sudden correlated drops across sectors), Jarvis proactively alerts all field operatives: "WARNING: Snap-pattern detected. All sectors showing coordinated depletion. Initiate emergency protocols." This is the "predict events before they happen" vision.

↗ THIS is the killer feature. Precognitive crisis prevention.

Tech Stack Combinations

The "Ship Fast" Stack

Next.js (fullstack) + SQLite + Recharts + OpenAI API

Minimal setup. One codebase. API routes built in. Deploy to Vercel in seconds. Focus all energy on features and polish.

The "Impress the Judges" Stack

React + Vite frontend + Python FastAPI backend + PostgreSQL + scikit-learn + spaCy NER

Shows polyglot skills. Python is better for ML. FastAPI is blazing fast. spaCy gives real NER for PII. Separate frontend/backend shows architecture.

The "All JavaScript" Stack

React + Express.js + MongoDB + TensorFlow.js + compromise.js (NER)

One language everywhere. MongoDB is fast to prototype. TF.js can run forecasting in-browser for a cool demo. compromise.js handles NER without Python.

The "Cloud Native" Stack

React + AWS Lambda + DynamoDB + Bedrock (Claude) + SageMaker

Full AWS play. Shows enterprise deployment skills. Bedrock for LLM (no API key management). Could be overkill for a hackathon but impressive if your team knows AWS.

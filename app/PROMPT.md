## UI Features

The UI will have the following features:

#### `\`
The home dashboard. 
IF the user is logged in, redirect to `/dashboard`, else display the `/login` page

#### `/login`
Display a basic login flow. (no need to implement sign-up). Include validation and loading/complete flows, before redirecting to `/dashboard`

#### `/dashboard` (can also just be `/` when logged in)
The dashboard is the main landing page for the application.
- ShadCN Sidebar Component persisting for this page and all other pages
- Top text displaying "Welcome <Name>"
- Three boxes displaying important information:
  - Top Right: Priority Event Reports, showing the head titles like that in a news page. Selecting it will show the full event report displayed/view-transitioned in a new page.
  - Bottom Right: Anonymous Hero Reports
  - Left: Globe display showing selected countries/regions on the globe with support for displaying mini-graph data on hover. The minigraph may have buttons or some click options to then view-transition/navigate to the analytics for the given country.

#### `/analytics`
Shows general real-time analytics for resources and sectors/regions over time, updated in real time using JS charts and listening to changes from rabbitmq. 

The MAJOR metric given from the data stream (metric `x`) is then used for the chart

Selecting a given country or resource shows more detailed analytics by the given category

#### `/analytics/sector/:sec`
Gets more detailed analytics for a given sector `sec`, showing the chart(s) for the different metrics plotted, including useful plots (like mean regression lines or whatever is suitable for the kind of data). The MAJOR metric graph should be highlighted first with useful data. This will be an addition of resources available for the given sector.

The major metric should contain plots for forecasts, and where the economy is planned to go. This should be queried from the server and be updated when new data reaches the chart, showing forecasts for where the data may go and how that'll look (most likely a linear line w/range-area from latest data point until end of forecast range). This should show for each necessary resource for the sector on its individual graphs, and in the general major graph.

There should also be sections for descriptions for why the forecast is what it is, which can be gotten through the forecast call (maybe the same endpoint or an extra endpoint).

#### `/analytics/resource/:name`
Gets more detailed analytics for a given resource `name`, showing the chart(s) for the different metrics plotted, including useful plots (like mean regression lines or whatever is suitable for the kind of data). The MAJOR metric graph should be highlighted first with useful data. The major graph here will be a "resource by country" map showing resource allocation for different countries

The major metric should contain plots for forecasts of the resource for each given country in a "resource by country" map for applicable countries, and where the economy is planned to go for each country. This should be queried from the server and be updated when new data reaches the chart, showing forecasts for where the data may go and how that'll look (most likely a linear line w/range-area from latest data point until end of forecast range).

There should also be sections for descriptions for why the forecast is what it is, which can be gotten through the forecast call (maybe the same endpoint or an extra endpoint).

#### `/event/:name`
Displays a complete event report for a given event that has occured, and what that means for given resources and other things, including references to charts and

#### `/reports/new`
Create a new report to submit to the backend, with the following fields:
- Name (Hero Alias)

Ensure basic validation.

report id and timestamp are autogenerated

The name and contact of the hero is sensitive, secure data, and is signed with the JWT from better-auth for the given user, and sent down to the backend with the authentication header providing the required JWT key. The JWT key and the signed/encrypted JWT data in the JSON payload will be used to get the encrypted data.

See the [`.jsonl`](./field_intel_reports.jsonl) file for sample of the minimum JSON data needed. The `metadata` info is secure, and will be JWT encrypted and signed (so should be a string upon transmission to backend, therefore).

The API call for the report should contain info concerning obvious things (like name, time, etc):
- report description
- affected resources
- affected locations
- reports that made up this event (list of ids)
- time started

This can be used for chart display, displaying the description and other stuff, report quotes and/or hints, etc. 

Basic event stuff will be sent via rabbitmq, which will be displayed in the main dasboard route, then when clicked, the endpoint is called

## Tech Stack

You will design this application in Nuxt v4. 

You should use:
- shadcn/vue for most of the components: The application will use shadcn-vue components for speedy development
- globe.gl for the globe view: The interactive globe view will make use of `globe.gl`, and will only highlight countries found in the API call to the backend.
- better-auth for authentication (using JWT plugin)
- rabbitmq for event streaming (read): RabbitMQ is used for asynchronous streaming and updating of UI as needed, mainly for analytics data where needed. Analysis data will be queried on main try, and new updates sent via RabbitMQ. Current events will be in a similar vein: First API call, then send data, unless RabbitMQ can queue data and send queued data sent from producer whenever consumer connects, which is fine. Toast calls should not be called for queued data, and only for events that happen after logging into the dashboard.
- tanstack vue for forms: The major form would be for sending rep
- zod for validation
